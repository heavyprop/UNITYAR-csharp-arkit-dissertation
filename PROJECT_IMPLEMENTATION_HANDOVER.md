# Manchester Museum AR Experience - Implementation Handover
This overview of the project is generated by AI, incase of hallucinations!

## 1. Project Summary

This project is a Unity augmented reality application that presents the history of life on Earth through a sequence of geological eras. The user starts in a timeline-style menu, chooses an era, enters an AR scene for that period, interacts with educational content, and returns to the timeline without restarting the app.

The application was built as a mobile AR experience, mainly for iPhone/iOS, using Unity 6, ARKit, Unity's Input System, UI Toolkit, UGUI, TextMesh Pro, URP post-processing, imported 3D asset packs, and custom C# scripts.

The main goal was not just to show static 3D models. The project combines AR scene navigation, educational storytelling, quizzes, touch interaction, raycasting, animated objects, sliders, visual effects, object placement, and additive scene loading into one museum-style experience.

## 2. What I Built

I built an AR educational app structured around one persistent base scene and multiple separate AR era scenes.

The base scene keeps the AR session, XR Origin, AR camera, UI navigation, and shared controls alive. When the user selects an era, the app loads that era's Unity scene additively on top of the base AR scene. When the user exits the era, that scene is unloaded and the app returns to the same timeline page.

The final build includes these main areas:

- A UI Toolkit timeline/menu system for browsing geological eras.
- Additive scene loading so each era can be developed as a separate Unity scene.
- ARKit/XR setup for camera tracking and AR interaction.
- Educational era scenes for Precambrian through Quaternary periods.
- Touch-based interactions using Unity's Input System.
- Physics raycasts from the AR camera to tap 3D objects.
- Quiz systems with answer feedback, wrong-answer lockout, and progression.
- Slider-driven environmental effects, including saturation, tint, water height, and extinction simulation.
- AR plane placement for placing a dinosaur prefab onto a detected floor.
- Scene exit flow that returns from AR content back to the timeline.
- Visual styling using UI Toolkit UXML/USS and TextMesh Pro world-space UI.

## 5. Core Architecture

The central architecture is:

1. `XR+UI.unity` starts first.
2. It contains the persistent AR setup and the `UIDocument`.
3. `EraNavigator.cs` displays one UXML page at a time.
4. Each page has buttons named `start-btn`, `next-btn`, and `back-btn`.
5. `next-btn` and `back-btn` move between timeline pages.
6. `start-btn` loads the matching AR scene additively.
7. While the AR scene is active, the timeline UI is hidden and disabled.
8. Each AR scene has its own local interaction scripts.
9. An exit button in the AR scene calls `ExitARScene.Exit()`.
10. `ExitARScene` finds the persistent `EraNavigator` and calls `ReturnToMenu()`.
11. `EraNavigator` unloads the additive scene and restores the same timeline page.

This design avoids duplicating the AR session in every scene. It also lets each era scene stay independent, which makes the project easier to build, test, and explain.

## 6. Main Script Responsibilities

### `EraNavigator.cs`

This is the main controller for the whole app.

Responsibilities:

- Stores an array of UI pages in `eraPages`.
- Stores an array of scene names in `arSceneNames`.
- Shows the correct UI Toolkit page.
- Hooks up `start-btn`, `next-btn`, and `back-btn`.
- Loads selected AR scenes additively.
- Displays the loading page while a scene loads.
- Hides and disables the timeline UI during AR scenes.
- Tracks the currently loaded scene in `loadedScene`.
- Uses a `busy` flag to prevent overlapping scene loads.
- Unloads the active scene and restores the menu when the user exits.

This script is the backbone of the project. It turns separate Unity scenes into one continuous AR app experience.

### `ExitARScene.cs`

This is attached to exit buttons inside AR scenes.

Responsibilities:

- Finds the active `EraNavigator` in the base scene.
- Calls `ReturnToMenu()`.
- Lets each AR scene return to the menu without directly managing scene unloading.

Each scene can share the same exit pattern instead of duplicating navigation code.

### `DimToggle.cs`

This controls a dim overlay tagged as `Dimmer`.

Responsibilities:

- Finds the dimmer object by tag.
- Hides it by default.
- Toggles it on/off through a button.

AR text can be hard to read over a real camera feed. The dimmer improves readability without changing the scene content.

## 8. Reusable Patterns

### Additive Scene Loading

The app avoids switching away from the base AR scene. Instead, it loads era scenes additively. This keeps the AR session stable and avoids duplicating XR setup.

### Inspector-Driven Configuration

Many scripts expose public fields for buttons, sliders, text, images, volumes, prefabs, and scene objects. These are connected in the Unity Inspector.

This was important because Unity apps are often built by combining C# logic with scene references rather than code alone.

### Coroutine-Based Timing

Coroutines are used for short delays and visual feedback:

- Quiz correct/wrong images appear for 0.5 seconds.
- Jurassic quiz starts after 6 seconds.
- Quaternary image fades in over several seconds.

### Raycast-Based Interaction

The app uses two kinds of raycasts:

- Physics raycasts from the AR camera to detect taps on 3D objects like bubbles or dinosaurs.
- AR raycasts from `ARRaycastManager` to detect real-world planes for object placement.

### Post-Processing as Interaction Feedback

The app uses URP `Volume` and `ColorAdjustments` to visually communicate environmental changes:

- Ordovician becomes colder and more desaturated.
- Triassic changes colour/tint based on slider position.
- Jurassic darkens/desaturates during the quiz to focus attention.

## 9. Main Problems I Solved

### Keeping AR Navigation Stable

Problem:

If each era scene had its own AR session, transitions would become messy and repeated.

Solution:

Use one persistent base scene with AR session and load only the content scenes additively.

### Making UI Work in AR

Problem:

AR scenes use camera feed backgrounds, world-space UI, UI Toolkit pages, UGUI buttons, and TextMesh Pro text. Input and readability can fail if cameras, canvases, or event systems are not configured correctly.

Solution:

Use a base scene for shared UI, assign/find AR cameras when needed, add a dimmer overlay, and keep scene UI grouped so it can be hidden or shown reliably.

### Tapping 3D Objects on Mobile

Problem:

A screen tap is only a 2D coordinate, but the objects are in 3D AR space.

Solution:

Convert the tap into a ray using the AR camera and test against colliders with `Physics.Raycast`.

### Placing Objects on Real Surfaces

Problem:

AR placement needs detected planes, not arbitrary screen positions.

Solution:

Use `ARRaycastManager.Raycast` against `TrackableType.PlaneWithinPolygon`, then check the surface is flat enough before instantiating a prefab.

### Creating Educational Interactions

Problem:

The app needed more than static labels.

Solution:

Add mini-interactions: bubble popping, quizzes, extinction slider, sea-level slider, dinosaur placement, animation trigger, and fade reveal.
